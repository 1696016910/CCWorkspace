# Spec Delta

## Purpose

保证应用在存储损坏、外部服务不可达、非法输入等异常条件下仍能启动、给出可读反馈，并且不留下无法恢复的中间状态。

## ADDED Requirements

### Requirement: 存储损坏时仍可启动

系统 MUST 在数据库文件不是有效的 SQLite 文件、或完整性检查失败时，备份原文件并以空数据库继续启动。

系统 MUST NOT 因数据库损坏而阻止窗口创建。

#### Scenario: 数据库文件被写坏

- **WHEN** `workbench.db` 被替换为非 SQLite 内容后启动应用
- **THEN** 应用窗口正常出现
- **THEN** 原文件被复制为 `workbench.db.corrupt-<时间戳>` 备份
- **THEN** 工作区与会话列表为空，但界面可正常操作

### Requirement: IPC 输入校验

系统 MUST 在创建会话、重命名、删除、保存配置等写操作前校验参数。

非法输入 MUST 返回可读的业务错误，MUST NOT 暴露底层数据库或运行时错误。

#### Scenario: 指定的工作区不存在

- **WHEN** 调用方以不存在的 workspaceId 创建会话
- **THEN** 返回「指定的工作区不存在」
- **THEN** 不出现外键约束等底层错误文本

#### Scenario: 重命名不存在的会话

- **WHEN** 对不存在的会话执行重命名
- **THEN** 返回「会话不存在」

### Requirement: 发送不阻塞主通道

发送消息的 IPC 调用 MUST 立即返回，回复通过事件流推送。

系统 MUST 在发送前同步校验空消息与并发，这类错误 MUST 立即返回给调用方。

#### Scenario: 发送后界面立即可交互

- **WHEN** 用户发送一条消息
- **THEN** IPC 调用在 100 毫秒内返回
- **THEN** 界面通过事件流逐步接收回复

### Requirement: 连接异常有超时兜底

系统 MUST 在指定时间内未收到任何有效响应事件时判定为连接失败。

hook 等系统事件 MUST NOT 被当作「服务已响应」。

失败时 MUST 结束生成状态，使用户可以再次发送。

#### Scenario: 服务不可达

- **WHEN** 模型服务持续无响应超过阈值
- **THEN** 界面显示连接超时提示
- **THEN** 输入框恢复可用

### Requirement: 渲染错误不扩散

界面 MUST 在子组件抛错时展示可恢复的错误面板，而非整页白屏。

用户 MUST 能通过「重试」重新挂载该区域。

#### Scenario: 对话区渲染异常

- **WHEN** 对话区域在渲染时抛出异常
- **THEN** 该区域显示错误提示与技术细节
- **THEN** 侧栏与其它区域仍然可用
