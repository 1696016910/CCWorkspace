# session-management Specification

## Purpose
在应用自己的数据库里持久化会话，按工作区分组并支持完整的生命周期操作，使日常工作的对话与开发用的 Claude Code 会话彻底隔离。

## Requirements

### Requirement: 会话由应用自行存储

系统 MUST 在应用私有数据库中保存会话及其消息。

系统 MUST NOT 读取 `~/.claude/projects/` 下的历史会话文件。

系统 MUST NOT 写入或修改任何 Claude Code 的会话文件。

#### Scenario: 首次启动时没有任何会话

- **WHEN** 用户首次安装并启动应用
- **THEN** 会话列表为空并显示空状态
- **THEN** 不显示磁盘上已有的 Claude Code 会话

#### Scenario: 应用内的会话不出现在终端

- **WHEN** 用户在应用内新建并完成一段对话
- **THEN** 终端中执行 `claude --resume` 不会看到该会话

### Requirement: 会话按工作区分组

系统 MUST 将会话归属于一个工作区，并在列表中按工作区分组展示。

系统 MUST 在同一工作区内按最近更新时间倒序排列会话。

#### Scenario: 多工作区的会话分组

- **WHEN** 应用内存在分属两个工作区的会话
- **THEN** 列表按工作区分组显示
- **THEN** 每个工作区内的会话按更新时间倒序

#### Scenario: 切换工作区后新建会话

- **WHEN** 用户在某工作区下新建会话
- **THEN** 该会话仅出现在该工作区分组下

### Requirement: 会话标题

系统 SHALL 在用户未命名时，使用该会话首条用户消息截断 40 个字符作为标题。

用户重命名后 MUST 使用新名称，且不再回退到首条消息。

#### Scenario: 新会话自动获得标题

- **WHEN** 用户新建会话并发送第一条消息「把订单接口改成幂等」
- **THEN** 列表中将该会话显示为「把订单接口改成幂等」

#### Scenario: 重命名后以新名称为准

- **WHEN** 用户将会话重命名为「订单幂等改造」
- **THEN** 列表中显示「订单幂等改造」

### Requirement: 新建会话

用户 SHALL 能在指定工作区下新建会话。

新建时若未指定工作区，系统 MUST 使用默认工作区。

若没有可用工作区，系统 MUST 阻止创建并提示先添加工作区。

#### Scenario: 在指定工作区新建

- **WHEN** 用户在某个工作区下点击「新建会话」
- **THEN** 创建归属于该工作区的新会话并进入对话界面

#### Scenario: 没有可用工作区

- **WHEN** 工作区列表为空时用户尝试新建会话
- **THEN** 系统提示需要先添加工作区，不创建会话

### Requirement: 会话删除

用户 SHALL 能删除会话。

删除 MUST 为软删除：会话被标记为已删除并从列表隐藏，数据保留在数据库中以便恢复。

用户 SHALL 能从回收站恢复被删除的会话。

#### Scenario: 删除会话

- **WHEN** 用户删除一个会话
- **THEN** 该会话从列表中消失
- **THEN** 其数据仍保留在数据库中被标记为已删除

#### Scenario: 恢复已删除的会话

- **WHEN** 用户在回收站中恢复一个会话
- **THEN** 该会话重新出现在原工作区分组下

### Requirement: 复制会话

用户 SHALL 能复制一个会话，生成一个包含相同历史但独立的新会话。

副本 MUST 拥有新的会话标识，后续对话 MUST NOT 影响原会话。

#### Scenario: 复制会话后独立演进

- **WHEN** 用户复制会话 A 得到会话 B，并在 B 中继续对话
- **THEN** 会话 B 拥有新的标识与独立的标题
- **THEN** 会话 A 的消息不因 B 的后续对话而改变

### Requirement: 消息持久化

系统 MUST 持久化每一轮对话中的用户消息与助手回复，使重启应用后能完整回放。

#### Scenario: 重启后历史仍在

- **WHEN** 用户完成一段对话后关闭并重新打开应用
- **THEN** 打开同一会话可以看到之前的全部消息
